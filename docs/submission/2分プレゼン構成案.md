## 1. 勝ち筋の整理（なぜこの構成か）

First Stageは約130提案→24枠（通過率約18%）の**動画大量審査**であり、第一印象で決まる（[research/02](../research/02-winners-and-competition.md)）。構成は次の4原則で設計する。

1. **冒頭10秒で「自分ごと」の問いを立てる。** 審査員も視聴者も、まず「自分はどの区か」と考えさせられた瞬間に当事者になる。課題説明から始めない。
2. **デモ動画を主役にする（40秒）。** 「アイデア力」の公式定義は「サービスとして成立しているか」。公開済み・動くもの・完成度をデモで一気に証明する。
3. **5軸すべてに証拠を1つずつ置く。** 1軸突出でも最低ライン割れがあると総合評価で落ちる（[research/01](../research/01-contest.md)）。台詞かスライドのどちらかで5軸全部に必ず触れる（§5のマッピング表）。
4. **「かわいい」の直後に必ず「実データ」を言う。** 本作最大の減点リスクは「キャラものでデータ活用が薄い」という誤解。デモ中とデータスライドの2回、「性格はすべて公式データの関数」であることを明言する。

過去最優秀の型（不安の可視化×命/QOL）とは意図的に違う土俵——**「オープンデータに馴染みのない都民の、最初の1クリックを作る」**——で戦う。劣化版YORUMICHI・熱中症マップの群れと被らないこと自体が差別化になる。

## 2. タイムライン（2:00枠 → 発話は95〜100秒で作る）

2分超過は強制終了。発話時間のほかに、スライド切替・埋込動画の再生開始操作・顔出し時の間で10〜15秒消費する前提を織り込み、**台本は500字以下（発話約95〜100秒）**とする。合格ラインは「動画の再生開始操作を含む通し収録で105秒以内」。最後の10秒（締めとチーム紹介）は絶対に削られないよう前に余裕を持たせる。

## 3. スライド構成の詳細

### ① 表紙（0:00–0:10）
- 作品名「うちの区ちゃん」＋サブコピー「オープンデータでできた、東京23区の性格診断図鑑」。
- 23区キャラの集合ビジュアル（トップ／ヒーローのキャプチャ流用可。提出キャプチャ1枚目と共通化）。
- 顔出し収録の第一声とビジュアルの情報量で勝負する。文字は最小限。

### ② 課題（0:10–0:30）
- 課題は1メッセージに絞る: **「区の取り組みやデータに、そもそも興味・関心がない」**。
- 根拠の数字を大きく1つ: 区の取り組みや身近な情報を**「特に入手していない」— 10代・20代の5〜6割**（男性10・20歳代54.2%／女性10・20歳代59.2%。全体でも25.2%＝4人に1人）。出典は世田谷区民意識調査2024（無作為抽出・n=2,404・問9）。
- この数字は「区の取り組み・情報への接点のなさ」の**直接測定**であり、投票率のような代理指標の飛躍がない。年代の傾斜（若いほど接点がない）が、③の「診断されたい」ターゲットとも一直線につながる。
- **世田谷区1区の調査である**ことを隠さない。口頭・スライドとも「例えば世田谷区の調査では」と言い、23区全体の数字と誤認させない。出典（報告書・クロス集計Excel・ローデータが公開＝根拠もオープンデータ）はスライドに明記する。
- 投票率（2023年統一地方選の区市町村議選44.98%・2025年11月葛飾区議選40.35%）は**主役から外し、使うとしても「地域への関心を考える一つの背景」としてスライドの脇に小さく**。比較や因果の結論には使わない（検証記録はチェックリストの表に残す）。都議選61.53%との対比は削除した（特異に高い年で一般化に使えないため）。
- 性別・年代別の数字であり特定の区を貶めないためスティグマ懸念は小さいが、「若者は無関心」と断定する言い方は避け、「接点がない」という事実の記述に留める。
- フォーム2-4（着目した課題）と同じ論旨にして、資料間で矛盾を作らない。

### ③ コンセプト（0:30–0:50）＝関心の矢印を逆転させるUX
- 導入のブリッジ: 「関心のない人に、情報（オープンデータ）を開示しても届かない」→ だから**関心の矢印を逆転させる**。
- インサイト: 16タイプ性格診断などの診断コンテンツがSNSでブームであるように、若い世代は「**自分がどうなのか**」には強い関心がある＝**“診断されたい”**。
- コンセプト図は矢印1本のUX図にする: **「自分を知りたい（診断されたい）」→ 10問診断 → 「あなたに一番似ている区」→ 区への興味 → 実データ・政策へ**。区の情報を“届ける”のではなく、自分への好奇心が区まで“引き寄せる”構造。
- 擬人化の役割もこの文脈で語る: 順位ではなく優劣のない“個性”として擬人化したから、「**私はどの区になるの？**」という興味が生まれる（スティグマ回避は結果として同時に達成される設計思想）。
- 「5つの公式統計 → 性格5軸 → 擬人化 → 最近傍マッチング」の**変換図はここでは出さず⑤へ移す**。③はUXの発想、⑤はその裏付け、と役割を分ける。
- 注: 「MBTI」は商標のため、スライド・口頭では「16タイプ性格診断」「性格診断ブーム」等の一般表現を使う。

### ④ デモ動画（0:50–1:30・40秒・無音）＝一本線で「診断が一次情報へ着地する」ことを証明
- 構成は**一本線**: **3D図鑑の世界観カット（2〜3秒） → 診断1問だけ → 結果（あなたの区ちゃん登場・レーダー） → 同じ区の詳細（実数値・出典・政策リンク）**。40秒で4場面を等分に流すのではなく、「診断 → 根拠 → 政策」の1ストーリーを読める速度で見せる。
- 削るもの: 10問の連続操作、にてる度・近い区TOP3・X共有の画面、地図の長回し。見せたい周辺要素（近い区3つ・共有カード等）は動画に入れず、**⑥の静止画やキャプチャに退避**する。
- 各場面にテロップ（例:「10問に答える」「あなたに一番似ている区」「根拠の実数値と出典」）と要所のズームを入れ、1600×900でも実数値・出典が読めることを書き出し後に実寸確認する。
- アプリ内表記は現行どおり（「相性TOP3」等）で、プレゼンの言葉選びのみ「近い区」「分布内の位置」へ寄せる（スティグマ回避方針との整合）。UI側の文言変更は別途検討。
- ナレーションは発表者が生声で行う（BGM・音声合成は使わない）。
- 動画の最後は区詳細の「出典」表示で止める。「かわいいの奥は全部実データ」の台詞と画が一致する。
- 実機収録はスマホ回線等に依存しない安定環境で行い、カーソル移動は遅めに。1600×900以上で書き出す。
- 注: フォーム3-8の**60秒操作動画は従来構成（図鑑→診断→結果→区詳細のフルツアー）のままでよい**。プレゼン40秒版はこの一本線構成で別編集とする。
- 制作方式の検討（HyperFrames等・未確定）は [デモ動画制作方針.md](デモ動画制作方針.md) を参照。

### ⑤ データと技術（1:30–1:45）
- 上段: 変換図「5つの公式統計 → [-1,1]の性格5軸（賑わい・成熟・みどり・世帯・華やぎ） → 23区の擬人化 → 10問診断で最近傍マッチング」（③から移設。“かわいい”の裏付けはここで見せる）。
- 中段: 利用オープンデータ10件（フォーム4-1の表と同一の名称・出典。読み上げず「10件」と総数だけ言う）。5軸に効く5件を太字で強調。
- 下段: アーキ図1行——「Python集計 → ビルド時にJSON同梱 → Next.js静的生成 → Cloudflare Pages配信。実行時サーバー・DB・認証なし」。
- 補強の数字を小さく: 23区×5軸、Vitest 251テスト、WebGL非対応・reduced motion時の2Dフォールバック。
- **「リアルタイムAPI連携」とは書かない**（実態は確定値のビルド時取り込み。[strategy設計書](../strategy/kuchan-shindan-zukan-design.md) §5の申し送り）。

### ⑥ 持続性とチーム（1:45–2:00）
- **「最初の1クリック」の先（QOL接続）を1文で閉じる**: 診断で終わらせず、実数値・出典・区の政策まで一画面でつなぎ、「自分に近い区」を入口に、**住まい選びや子育てなど暮らしの判断に使える一次情報へ誰でも到達できるようにする**。約束するのは「到達障壁を下げる」まで（効果の断定はしない）。
- ④の動画から退避した周辺要素（近い区3つ・共有カード）はここに静止画で置き、シェア→再訪の広がりを見せる。
- 広がり: 「診断結果カード」と「地元カード」の二重シェア導線、GA4による匿名計測→改善、年1回のデータ棚卸し運用（フォーム1-9と同旨）。
- チーム紹介（提出必須要素）: 個人開発である旨＋役割（企画・データ分析・デザイン・開発・運用）。生成AI活用は「キャラクター画像の生成と開発補助に活用」の一言に留める（AI活用は全員が使える前提で差別化にならない）。
- 最後にデモURL＋QRコード。「あなたの区ちゃんに会いに来てください」で締める。

## 4. 読み上げ台本ドラフト（478字 ≒ 発話96秒 @300字/分）

> 【①】あなたにいちばん“似ている”東京の区。どこだと思いますか？
>
> 【②】例えば世田谷区の調査では、区の取り組みや身近な情報を「特に入手していない」人が、10代・20代で半数を超えます。区のデータは、多くの都民にとって“関心の外”にあります。
>
> 【③】でも、性格診断がブームなように、誰でも“自分”には興味がある。そこで発想を逆転。10問の診断で、あなたにいちばん似ている区と出会わせます。順位のない“個性”への擬人化だから、「私はどの区？」という好奇心が生まれます。
>
> 【④】実際の画面です。質問に答えると——あなたの区ちゃんが登場。そのまま区の詳細へ進むと、実数値、出典、区の政策まで一画面でつながります。かわいいの奥は、すべて実データです。
>
> 【⑤】昼夜間人口比率や財政力指数など、公式オープンデータ10件を23区共通の5軸に変換。静的サイトなので運用コストと障害要因を抑えた、引き継ぎやすい構成です。
>
> 【⑥】診断は入口。似ている区をきっかけに、住まいや子育てなど暮らしの判断に使える一次情報へ、誰でも届く——それが「うちの区ちゃん」です。個人で制作し、公開済み。あなたの区ちゃんに、会いに来てください。

- 実測478字（①29・②84・③108・④84・⑤76・⑥97）。300字/分で発話約96秒、スライド切替・動画開始操作・間を足しても105〜110秒に収まる設計。
- 収録前に**動画の再生開始操作を含む通し**で3回以上計測し、105秒以内に収まるまで削る。削る優先順位: ③の最終文 → ⑤の具体名列挙 → ②の最終文。
- 【①】と【⑥】の言い回しだけは暗唱できるまで固める（冒頭と締めが印象を決める）。

## 6. やってはいけないこと（減点・失格リスク）

- **2分超過**（強制終了）。台本500字以下・通し収録105秒以内の設計を崩さない。
- 「リアルタイムAPI連携」等の過大表記。正しくは「公式オープンデータの最新確定値をビルド時に取り込み」。
- 「性格」「相性」の断定・予測的表現（over-claim）。遊びのフレームであることを崩さない。
- 「このアプリで投票率が上がる」「関心が高まる」と効果を断定しない。約束するのは「関心の入口を作る」「一次情報への到達障壁を下げる」まで。
- 区の否定的ラベル・優劣演出。順位を見せる場合も「個性の位置」として中立に。
- BGM・効果音・音声合成。デモ動画は無音、ナレーションは生声。
- 出典なしの画面引用。統計表キャプチャ・地図には出典と「加工して作成」を明記。
- AI活用の強調。参加者全員が使える前提であり、話すほど時間対効果が悪い。
- ライブデモ前提の話し方（「今から操作します」等）。すべて動画で完結させる。
- PDFを収録マスターにしない（埋込動画の再生が保証されないため）。
- スライドの文字の詰め込み。1枚1メッセージ、台詞で補う。
