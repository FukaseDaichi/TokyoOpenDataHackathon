# First Stage 2分プレゼン構成案

「うちの区ちゃん」First Stage収録（2026年8月26日〜30日）で使うプレゼン資料の構成案。提出要件は [提出資料について.md](提出資料について.md)、フォーム入力は [作品提出フォーム回答案.md](作品提出フォーム回答案.md) を正とする。

- 作成日: 2026-07-31
- 形式: PowerPointまたはPDF／16:9横／2分厳守（超過は強制終了）
- 収録: 顔出し・事前収録。ライブデモ不可のためデモは**無音動画をスライドに埋め込む**

---

## 1. 勝ち筋の整理（なぜこの構成か）

First Stageは約130提案→24枠（通過率約18%）の**動画大量審査**であり、第一印象で決まる（[research/02](../research/02-winners-and-competition.md)）。構成は次の4原則で設計する。

1. **冒頭10秒で「自分ごと」の問いを立てる。** 審査員も視聴者も、まず「自分はどの区か」と考えさせられた瞬間に当事者になる。課題説明から始めない。
2. **デモ動画を主役にする（40秒）。** 「アイデア力」の公式定義は「サービスとして成立しているか」。公開済み・動くもの・完成度をデモで一気に証明する。
3. **5軸すべてに証拠を1つずつ置く。** 1軸突出でも最低ライン割れがあると総合評価で落ちる（[research/01](../research/01-contest.md)）。台詞かスライドのどちらかで5軸全部に必ず触れる（§5のマッピング表）。
4. **「かわいい」の直後に必ず「実データ」を言う。** 本作最大の減点リスクは「キャラものでデータ活用が薄い」という誤解。デモ中とデータスライドの2回、「性格はすべて公式データの関数」であることを明言する。

過去最優秀の型（不安の可視化×命/QOL）とは意図的に違う土俵——**「オープンデータに馴染みのない都民の、最初の1クリックを作る」**——で戦う。劣化版YORUMICHI・熱中症マップの群れと被らないこと自体が差別化になる。

## 2. タイムライン（2:00設計 → 台本は1:50で作る）

2分超過は強制終了のため、**台本は1分50秒（±5秒）で固定**し、10秒をバッファにする。日本語の発表速度目安300〜320字/分に対し、台本は約560字とする。

## 3. スライド構成の詳細

### ① 表紙（0:00–0:10）
- 作品名「うちの区ちゃん」＋サブコピー「オープンデータでできた、東京23区の性格診断図鑑」。
- 23区キャラの集合ビジュアル（トップ／ヒーローのキャプチャ流用可。提出キャプチャ1枚目と共通化）。
- 顔出し収録の第一声とビジュアルの情報量で勝負する。文字は最小限。

### ② 課題（0:10–0:30）
- 課題は1メッセージに絞る: **「区の取り組みやデータに、そもそも興味・関心がない」**。
- 根拠の数字を大きく1つ: **区議会議員選挙の投票率44.98%**（2023年統一地方選・東京都選挙管理委員会）＝「最も身近な選挙で、2人に1人以上が投票していない」。直近の2025年11月葛飾区議選でも40.35%（葛飾区選管）。
- 補強の対比（任意・スライドの脇に小さく）: 同じ都民でも2025年6月都議選の投票率は61.53%（都選管）。**身近な区の選挙ほど関心が低い**、という落差で課題を立体化できる。
- 「20代は2割台」という年代別の言及は**使わない**。区議選の年代別推定投票率は都選管調査が2011年分（20代22.01%）で止まっており、最新の2025年都議選では20代推定51.7%へ急上昇しているため、古い数字を出すと事実誤認を突かれる。
- 区別のワースト順位は出さない（スティグマ回避）。使うのは44.98%（統一分全体）と40.35%（葛飾・直近例）の2数値＋任意の都議選対比まで。
- 課題の根拠自体がオープンデータ（都選管の投票率一覧・年代別調査CSV）である点は、口頭では言わずスライドの出典表記で示す。
- フォーム2-4（着目した課題）と同じ論旨にして、資料間で矛盾を作らない。

### ③ コンセプト図（0:30–0:50）
- 導入のブリッジ: 「関心のない人に、統計表や順位の一覧は届かない」→ だから“出会い方”を変える。
- 1枚の変換図: 「5つの公式統計 → [-1,1]の性格5軸 → 23区の擬人化 → 10問診断で最近傍マッチング」。
- 5軸名（賑わい・成熟・みどり・世帯・華やぎ）とレーダーの実物を小さく添える。
- ここで「順位ではなく、優劣のない“個性”として見せる」を明言する。順位表示がもたらす優劣・スティグマの回避は課題ではなく**設計思想（コンセプト）として語る**（ソーシャルインパクトの証拠）。

### ④ デモ動画（0:50–1:30・40秒・無音）
- 構成はフォーム回答案3-8と同一: **3D/2D図鑑 → 10問診断の一部（2〜3問） → 結果（区ちゃん登場・レーダー・にてる度・相性TOP3・X共有） → 区詳細（東京23区地図・実数値・順位・出典・政策リンク）**。
- ナレーションは発表者が生声で行う（BGM・音声合成は使わない）。
- 動画の最後は区詳細の「出典」表示で止める。「かわいいの奥は全部実データ」の台詞と画が一致する。
- 実機収録はスマホ回線等に依存しない安定環境で行い、カーソル移動は遅めに。1600×900以上で書き出す。

### ⑤ データと技術（1:30–1:45）
- 上段: 利用オープンデータ10件（フォーム4-1の表と同一の名称・出典。読み上げず「10件」と総数だけ言う）。5軸に効く5件を太字で強調。
- 下段: アーキ図1行——「Python集計 → ビルド時にJSON同梱 → Next.js静的生成 → Cloudflare Pages配信。実行時サーバー・DB・認証なし」。
- 補強の数字を小さく: 23区×5軸、Vitest 251テスト、WebGL非対応・reduced motion時の2Dフォールバック。
- **「リアルタイムAPI連携」とは書かない**（実態は確定値のビルド時取り込み。[strategy設計書](../strategy/kuchan-shindan-zukan-design.md) §5の申し送り）。

### ⑥ 持続性とチーム（1:45–2:00）
- 広がり: 「診断結果カード」と「地元カード」の二重シェア導線、GA4による匿名計測→改善、年1回のデータ棚卸し運用（フォーム1-9と同旨）。
- チーム紹介（提出必須要素）: 個人開発である旨＋役割（企画・データ分析・デザイン・開発・運用）。生成AI活用は「キャラクター画像の生成と開発補助に活用」の一言に留める（AI活用は全員が使える前提で差別化にならない）。
- 最後にデモURL＋QRコード。「あなたの区ちゃんに会いに来てください」で締める。

## 4. 読み上げ台本ドラフト（約560字 ≒ 1分50秒）

> 【①】あなたにいちばん“似ている”東京の区。どこだと思いますか？——データが教えてくれます。
>
> 【②】東京23区の区議会議員選挙、投票率は45%。最も身近な選挙なのに、2人に1人以上が投票していません。区の取り組みも、区のデータも、多くの都民にとって“関心の外”にある——これが課題です。
>
> 【③】関心のない人に、統計表や順位の一覧は届きません。そこで「うちの区ちゃん」。公式統計を23区共通の性格5軸に変換し、23区を擬人化しました。10問の診断で、あなたの回答ベクトルに最も近い区とマッチングします。順位ではなく、優劣のない“個性”として出会い直すのがコンセプトです。
>
> 【④】実際の画面です。3D図鑑で23区の区ちゃんに出会い、10問に答えると——あなたの区ちゃんが登場。レーダーと“にてる度”、相性TOP3が出ます。そのまま区の詳細に進むと、実数値、23区の中での位置、出典、そして区の政策まで届きます。かわいいの奥は、すべて実データです。
>
> 【⑤】使ったのは昼夜間人口比率、年齢構成、公園面積、世帯構成、財政力指数など、公式オープンデータ10件。ビルド時に取り込んで静的サイトとして配信するので、サーバーもデータベースもなく、落ちない・速い・低コストで行政でもそのまま持てる構成です。
>
> 【⑥】診断結果はXでシェアされ、地元愛が次の利用者を連れてきます。企画からデータ分析、開発まで個人で制作し、公開済みです。オープンデータへの“最初の1クリック”を、23区のみんなに。「うちの区ちゃん」でした。

- 収録前に3回以上通しで計測し、1:50±5秒に収まるまで削る。削る優先順位: ⑤の具体名列挙 → ②の2文目 → ⑥のシェア文。
- 【①】と【⑥】の言い回しだけは暗唱できるまで固める（冒頭と締めが印象を決める）。

## 6. やってはいけないこと（減点・失格リスク）

- **2分超過**（強制終了）。台本1:50設計＋バッファ10秒を崩さない。
- 「リアルタイムAPI連携」等の過大表記。正しくは「公式オープンデータの最新確定値をビルド時に取り込み」。
- 「性格」「相性」の断定・予測的表現（over-claim）。遊びのフレームであることを崩さない。
- 「このアプリで投票率が上がる」と言わない。投票率は関心の低さを示す**代理指標**として使い、約束するのは「関心の入口を作る」まで。
- 区の否定的ラベル・優劣演出。順位を見せる場合も「個性の位置」として中立に。
- BGM・効果音・音声合成。デモ動画は無音、ナレーションは生声。
- 出典なしの画面引用。統計表キャプチャ・地図には出典と「加工して作成」を明記。
- AI活用の強調。参加者全員が使える前提であり、話すほど時間対効果が悪い。
- ライブデモ前提の話し方（「今から操作します」等）。すべて動画で完結させる。
- スライドの文字の詰め込み。1枚1メッセージ、台詞で補う。
