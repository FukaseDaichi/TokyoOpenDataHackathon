# デモ動画制作方針（A案採用・初版制作済み）

First Stageプレゼンに埋め込む40秒デモ動画と、提出フォーム3-8用の60秒操作動画の制作方針。**A案（HyperFrames）を採用し、2026-08-03に40秒版の初版を制作済み**（`presentation/demo-40s-draft.mp4`）。構成の正典は [2分プレゼン構成案.md](2分プレゼン構成案.md) スライド④。

## 制作環境（構築済み）

- プロジェクト: `tools/demo-video/`（`index.html` がタイムライン定義。`npm run check` → `npm run render`）
- FFmpeg 8.1.2 をwingetで導入済み。シェルによってはPATH未反映のため `%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg_...\ffmpeg-8.1.2-full_build\bin` を通す
- 素材: `docs/submission/presentation/raw.mp4`（2026-08-03収録・1920×1200・2分33秒）を `tools/demo-video/assets/` へコピーして参照
- 素材が16:10のため `object-fit: cover`＋`scale(1.02)` で16:9化し、右端のスクロールバーを画面外へ
- 動画原本・レンダリング生成物はサイズが大きいため `.gitignore` 済み（コミットしない）

## 40秒版のカット表（第2版・2026-08-03・raw.mp4の時刻対応）

| 完成尺 | 場面 | raw.mp4 | テロップ |
|---|---|---|---|
| 0–4s | 3D絵本ヒーロー（タイトル） | 3–7s | なし |
| 4–10s | 3D絵本ヒーロー（絵本スクロール） | 31–37s | なし |

| 26–40s | 区詳細の実数値スクロール→出典で静止（下記2段ズーム） | 130–144s | 「オープンデータの実数値と出典」 |

### 場面4のズーム設計（2段）

| 完成尺 | 動き | 倍率・原点 | ねらい |
|---|---|---|---|
| 26.8–29s | 寄る（32.5–34.5sで戻す） | 1.55倍／原点 62% 45% | レーダーと実数値バーを読ませる |
| 37–39.2s | 寄って40sまで保持 | 2.1倍／原点 71% 91% | **最重要の「出典」を全文読める大きさで見せて終わる** |

原点は「可視窓の中心が対象の中心に一致する」よう逆算する。可視窓は `[o − o/s, o + (1−o)/s]` であり**原点を中心にはならない**ため、対象中心 `c` に対して `o = (2cs − 1) / (2s − 2)`。出典カード中心 `c ≒ (0.617, 0.723)`、`s = 2.1` から `o ≒ (0.71, 0.91)`。この逆算を省くと片側が画面外に切れる。

修正は `tools/demo-video/index.html` の `data-media-start`/`data-duration`/テロップ文言を書き換えて再レンダリング（決定的なので同じ入力は同じ出力）。

## 編集方式の選択肢

### A案（推奨・保留中）: HyperFrames ＋ コーディングエージェント

[HyperFrames](https://hyperframes.app/) は HeyGen が2026年4月に公開したOSSの動画フレームワーク。「HTMLで動画を書く」方式で、AIエージェントがタイムラインをコードとして記述し `npx hyperframes render` でMP4化する。

- 既存MP4素材を `<video>` タグ＋ `data-start`/`data-duration` で埋め込み可能（＝カット編集をコードで書ける）
- テロップはHTML/CSSで自由（デッキと同一トーンにできる）。ズームはCSS `transform: scale()` で実装
- **決定的レンダリング**: 同じ入力→同じ動画。「③を2秒短く」等の日本語指示→再レンダリングの反復が効く
- 要件: Node.js 22以上（本環境は22.16で充足）＋ FFmpeg（未導入。`winget install ffmpeg` で入る）
- 懸念: 新しいツールのため動画シークの挙動は要検証。モーションブラー等の高度表現は苦手（今回は不要）
- 参考: [TechLabs解説](https://data-engineering.jp/hyperframes/)／[Premiere・Remotion・HyperFrames比較](https://ai-bou.co.jp/use-case/hyperframes-video-generation)（「単発ならHyperFrames、テンプレ量産ならRemotion」）

### B案（フォールバック）: FFmpeg直編集 ＋ コーディングエージェント

concat（カット）・zoompan/crop（ズーム）・drawtext（テロップ）をスクリプト化。追加ツール不要で最も堅牢だが、テロップの表現力はHTML/CSSに劣る。A案が動かない場合に同じ素材・同じ秒割りで切り替え可能。

### C案（不採用方向）: GUI系AI自動編集ツール

FocuSee・Canvid・Screenify Studio・Screenforge 等はカーソル追従の自動ズームが得意。ただし、AI字幕は音声書き起こしベースが多く**無音の本動画では機能しない**（テロップは結局手動）、無料プランの透かしは提出資料でNG、デッキとのトーン統一が難しい。今回の要件には合わない。

## 収録（どの案でも共通・人がやる作業）

1. OBS Studio（無料）でフルHD収録。ブラウザはF11全画面（URLバー・ブックマーク・拡張アイコンの写り込み防止）
2. 素材クリップを場面ごとに分けて録る（各10〜20秒・複数テイク可。ミスはカットで拾う）
   - ① 3D図鑑をぐるっと見る／② 診断で1問答える／③ 結果表示／④ 区詳細をスクロール（実数値→出典→政策）
3. カーソルはゆっくり。回線・マシンが安定した環境で（3Dは滑らかに動く端末で）
4. 補助案: Playwrightで操作を自動再生してから録ると、テイクのばらつきがなくなり撮り直しが楽（必要なら操作スクリプトをエージェントが作成）
