# デモ動画制作方針（A案採用・35秒版）

First Stageプレゼンに埋め込む35秒デモ動画と、提出フォーム3-8用の60秒操作動画の制作方針。**A案（HyperFrames）を採用**。2026-08-14に素材を撮り直し、35秒版へ再編集した（`presentation/demo-35s-draft.mp4`）。構成の正典は [2分プレゼン構成案.md](2分プレゼン構成案.md) スライド④。

## 制作環境（構築済み）

- プロジェクト: `tools/demo-video/`（`index.html` がタイムライン定義。`npm run check` → `npm run render`）
- HyperFrames CLIのピンは 0.7.108（2026-08-14に0.7.90から更新、`npm run check` 通過を確認済み）
- FFmpeg 8.1.2 をwingetで導入済み。シェルによってはPATH未反映のため `%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg_...\ffmpeg-8.1.2-full_build\bin` を通す
- 素材: `docs/submission/presentation/chrome_jqYb3la7nj.mp4`（**2026-08-14再収録**・1920×1200・74.3秒・結果は渋谷区ちゃん/にてる度81%）を `tools/demo-video/assets/raw2.mp4` へコピーして参照。旧素材 `raw.mp4`（2026-08-03収録・港区83%）は40秒版の再現用に残置
- 素材が16:10のため `object-fit: cover`＋`scale(1.02)` で16:9化し、右端のスクロールバーを画面外へ
- 動画原本・レンダリング生成物はサイズが大きいため `.gitignore` 済み（コミットしない）

## 35秒版の設計（2026-08-14・raw2.mp4の時刻対応）

伝えたい4つのポイントを「POINT 1〜4」のポップ字幕（バッジ＋弾む登場）で順に出す構成。

| 完成尺 | 場面 | raw2.mp4 | ポップ字幕 |
|---|---|---|---|
| 0–5s | 3D絵本ヒーロー（タイトル→カード群フライスルー） | 0.5–5.5s | POINT 1「あなたは、何区タイプ？」（性格診断の入口で自分ごと化） |
| 5–12s | 診断（休日の過ごし方→回答→ページ捲り→次の質問） | 19.5–26.5s | POINT 2「かんたん10問に答えるだけ」 |
| 12–21s | 最終問回答→本が閉じて結果リビール（渋谷区ちゃん・にてる度カウントアップ81%） | 39.3–48.3s | POINT 3「一番似ている区と出会える」（カウントアップ完了後の15.9sから表示） |
| 21–35s | 区詳細スクロール（地図→レーダー→実数値→なかま）→**出典ズームで静止** | 59.5–73.5s | POINT 4「気になったら一次情報へ——ぜんぶ出典つき」（34.5sまで出し続ける） |

### 字幕のトーン

- 「重要なポイント！」感を出すポップ寄せ。金色バッジ（POINT n・-6度傾き）＋ピル本体（-1.5度傾き）＋ `back.out(1.9)` の弾む登場
- 配色はデッキと同トーンを維持（游明朝・金`#B8923F`・クリーム`#F4E8D0`、強調語のみ明るい金`#E8C56A`）
- バッジはピルに意図的に重ねるため `data-layout-allow-overlap` を付ける（layoutチェックの誤検知回避）

### 場面4のズーム設計（2段・出典ズームが最重要）

| 完成尺 | 動き | 倍率・原点 | ねらい |
|---|---|---|---|
| 25.3–27.3s | 寄る（29.8–31.4sで戻す） | 1.5倍／原点 84.5% 35% | レーダーと実数値バーを読ませる |
| 32.2–34.4s | 寄って35sまで保持 | 2.2倍／原点 71% 41% | **最重要の「出典」を全文読める大きさで見せて終わる** |

原点は「可視窓の中心が対象の中心に一致する」よう逆算する。可視窓は `[o − o/s, o + (1−o)/s]` であり**原点を中心にはならない**ため、対象中心 `c` に対して `o = (2cs − 1) / (2s − 2)`。この逆算を省くと片側が画面外に切れる。

- 出典カード中心はraw2.mp4の73.5s静止フレームを実測: 1920×1200上で(1180, 548) → 16:9クロップ（上下60px切り落とし）換算で `c ≒ (0.615, 0.452)`。`s = 2.2` → `o ≒ (0.71, 0.41)`
- 実数値バー領域は `c ≒ (0.615, 0.45)`、`s = 1.5` → `o ≒ (0.845, 0.35)`

修正は `tools/demo-video/index.html` の `data-media-start`/`data-duration`/字幕文言を書き換えて再レンダリング（決定的なので同じ入力は同じ出力）。

## 要件（確定済み）

- 35秒・**無音**（BGM・音声合成は大会規約上回避。ナレーションは収録時に生声）
- 一本線構成: 3D図鑑の世界観カット → 診断1問 → 結果（区ちゃん・にてる度） → 区詳細（実数値・出典）→ **出典ズームで静止**
- 4つの重要ポイントをポップ字幕で明示（上記カット表）
- 1600×900以上、透かし・第三者ロゴ焼き込み禁止、出来上がりはPowerPointへローカル埋め込み
- フォーム3-8用の60秒フルツアー版は同じ素材から別編集
- デモで見せる結果の区は固定する（回答パターンを事前に決めて毎回同じ結果を出す）。**2026-08-14収録は渋谷区ちゃん・にてる度81%**

## 編集方式の選択肢

### A案（採用）: HyperFrames ＋ コーディングエージェント

[HyperFrames](https://hyperframes.app/) は HeyGen が2026年4月に公開したOSSの動画フレームワーク。「HTMLで動画を書く」方式で、AIエージェントがタイムラインをコードとして記述し `npx hyperframes render` でMP4化する。

- 既存MP4素材を `<video>` タグ＋ `data-start`/`data-duration` で埋め込み可能（＝カット編集をコードで書ける）
- テロップはHTML/CSSで自由（デッキと同一トーンにできる）。ズームはCSS `transform: scale()` で実装
- **決定的レンダリング**: 同じ入力→同じ動画。「③を2秒短く」等の日本語指示→再レンダリングの反復が効く
- 要件: Node.js 22以上（本環境は22.16で充足）＋ FFmpeg（導入済み）

### B案（フォールバック）: FFmpeg直編集 ＋ コーディングエージェント

concat（カット）・zoompan/crop（ズーム）・drawtext（テロップ）をスクリプト化。追加ツール不要で最も堅牢だが、テロップの表現力はHTML/CSSに劣る。A案が動かない場合に同じ素材・同じ秒割りで切り替え可能。

### C案（不採用）: GUI系AI自動編集ツール

FocuSee・Canvid・Screenify Studio・Screenforge 等はカーソル追従の自動ズームが得意。ただし、AI字幕は音声書き起こしベースが多く**無音の本動画では機能しない**（テロップは結局手動）、無料プランの透かしは提出資料でNG、デッキとのトーン統一が難しい。今回の要件には合わない。

## 収録（どの案でも共通・人がやる作業）

1. OBS Studio（無料）でフルHD収録。ブラウザはF11全画面（URLバー・ブックマーク・拡張アイコンの写り込み防止）
2. 素材クリップを場面ごとに分けて録る（各10〜20秒・複数テイク可。ミスはカットで拾う）
   - ① 3D図鑑をぐるっと見る／② 診断で1問答える／③ 結果表示／④ 区詳細をスクロール（実数値→出典）
3. カーソルはゆっくり。回線・マシンが安定した環境で（3Dは滑らかに動く端末で）。**出典セクションで静止して数秒待ってから収録を終える**（末尾ズームの静止画になる）
4. 補助案: Playwrightで操作を自動再生してから録ると、テイクのばらつきがなくなり撮り直しが楽（必要なら操作スクリプトをエージェントが作成）
