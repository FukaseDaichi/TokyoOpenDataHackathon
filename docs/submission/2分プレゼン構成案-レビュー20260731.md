- 部分対応: P2-1（締めで作品名を回収する一文は台本⑥に反映。冒頭との同一文回収・名称の完全一致確認は未実施）／P2-2（台本の診断ブーム表現を「性格診断がブームなように」へ軽減。スライド③の記述はインサイト説明として残置）

**総評（Codex）**: 完成した動く作品と明快な入口を持つ点で通過可能性はあるが、2分の実測余裕がなく、課題根拠から社会的効果までの因果が飛んでいるため、このままでは約18%のFirst Stageを突破するには弱い。

## P0（このままだと落ちる／失格級）

### P0-1. 「1分50秒設計」が実質的に成立していない（Codex）

- 台本は実測約588字。300字/分で約118秒、320字/分でも約110秒であり、スライド切替・埋込動画の再生開始・顔出し時の間が一切織り込まれていない。「10秒バッファ」と言いながらタイムライン表は120秒を使い切っており矛盾。超過は強制終了で、締めとチーム紹介が切れる。
- **修正案**: 台本を発話だけで95〜100秒（500字以下）に削る。削減対象は⑤の技術スタック列挙と⑥の自己紹介文。動画開始操作を含む通し収録で105秒以内を合格ラインにする。

## P1（通過率を明確に下げる）

### P1-1. 投票率→「区のデータへの関心不足」の論理が弱い（Codex）

- 投票率は政治参加の指標であり、区のデータ・政策への関心を直接示さない。比較している選挙（2023統一分44.98%／2025葛飾40.35%／2025都議選61.53%）は年・種別・範囲が異なる。出典名「区市町村議会議員選挙投票率（統一分）」が台本の「東京23区の区議会議員選挙」と完全同義かも未確認（統一分には市町村を含む可能性）。行政系審査員ほど因果の飛躍を見る。
- **修正案**: 「投票率が低いからデータに関心がない」という断定を避け、投票率は「地域への関心を考える一つの背景」に格下げする。課題文は「区の情報は、必要になった時だけ探されがち。普段は開かれにくい統計や政策への入口を、自分ごと化する体験として作った」程度に限定する。

### P1-2. インパクトの到達点が「興味を持つ」で止まりQOL接続がない（Codex＋Claude）

- 公式のソーシャルインパクト軸はQOL貢献＋実現可能性を要求。「最初の1クリック」はコピーとして良いが、クリック後に何が変わるかが不明。②で出した投票率の数字が⑥で回収されない。
- **修正案**: 実装済みの範囲だけで一段具体化する。「診断で終わらせず、実数値・出典・政策ページまで一画面でつなぎ、都民が『自分に近い区』を入口に比較可能な一次情報へ到達できるようにした」。成果は「一次情報への到達障壁を下げる」に固定し、投票率向上は約束しない。

### P1-3. 40秒デモの詰め込みすぎ（Codex＋Claude）

- 4場面＋結果・詳細の情報要素過多で、審査員には「可愛い診断」しか残らない。最大の減点懸念「データ活用が薄いキャラもの」の見え方をむしろ強める。ズーム・テロップ設計の指示もない。
- **修正案**: デモの主役を「診断1問だけ → 結果 → 同じ区の根拠数値・出典・政策リンク」の一本線に絞る。3D図鑑は冒頭2〜3秒の世界観カット、相性TOP3・X共有・順位は削るか静止画の周辺要素へ。「診断が一次情報へ着地する」ことを読める速度で一度証明する。

### P1-4. ⑤が15秒で「用語の羅列」になる（Codex＋Claude）

- 変換図＋データ10件＋技術スタック＋数字は読めない。テスト数やフレームワーク名はこの時間では成果の証明にならない。
- **修正案**: 実在する一つの区を例に「公式値 → 正規化した5軸 → その区のレーダー → 診断結果」の変換を大きく見せる。データ件数・テスト・フォールバックは小さな補足に格下げ。

### P1-5. 「落ちない」「行政でもそのまま持てる」は過大表現（Codex）

- 静的配信でも「落ちない」は断言できない。「行政でもそのまま持てる」も運用主体・調達プロセスを示さない限り証明にならない。運用は個人前提であり主張と証拠が釣り合わない。
- **修正案**: 「実行時APIやDBを持たないため、運用コストと障害要因を抑えた」「データ更新手順と静的配信を分離しており、引継ぎ可能な構成」まで表現を下げる。

### P1-6. PDF化チェックと動画埋め込みが衝突（Codex＋Claude）

- PDFでは埋込動画の再生を保証できない。チェックリストの「PDF化して100MB以下」のままだと、収録マスターが未決でデモ不再生（必須4要素の毀損）リスク。
- **修正案**: 収録用マスターは「MP4をローカル埋込したPowerPoint」に固定し、収録端末でオフライン再生まで確認。PDFは提出用の静的控えと位置づける。

### P1-7. 持続性の説明が「計測する」以上に進んでいない（Codex）

- GA4は手段であり、誰が何を見てどう更新判断するかの答えになっていない。個人開発の強調は継続主体への疑問を生む。
- **修正案**: 年次更新を「公式データの更新確認 → スクリプト再生成 → 23区分の整合チェック → 静的再配信」の一行に落とす。GA4は「詳細ページ到達・出典クリックを匿名で確認し導線を改善」と計測対象まで具体化。

### P1-8. スライドの自立性不足（Claude）

- First Stageは動画＋資料の書類審査であり、資料単体でも読まれ得る。「文字最小限・台詞で補う」方針のままだと、資料だけ見た審査員に②③⑥の論旨が伝わらない。
- **修正案**: 各スライドに結論1行のキャプションを置き、資料単体で流れが追える最低限の自立性を確保する。

## P2（改善余地）

### P2-1. 作品名と「何が新しいか」の記憶固定が弱い（Codex）

- 冒頭と締めを同じ一文で回収する（例:「『うちの区ちゃん』は、23区の公式データを、あなたに似た区との出会いに変えるサービスです」）。提出フォーム・表紙・URL上の名称の完全一致を確認。

### P2-2. 「診断ブーム」「若い世代」が無根拠（Codex）

- データ活用を看板にする作品が最重要インサイトを無根拠で置くと全体の厳密さを下げる。「診断コンテンツに親しむ人は多い」程度に弱めるのが2分では安全。

### P2-3. 「相性TOP3」「順位」はスティグマ回避方針と緊張（Codex）

- プレゼンでは「近い区3つ」「5軸上の位置」へ言い換える。順位は優劣ではなく分布内の位置として見せる。

### P2-4. 「3D/2D図鑑」のスラッシュ表記（Codex）

- 完成形が未決の印象を与える。本編は3Dを見せ、「WebGL非対応時も同じ情報に到達できる2D表示」と一言添える。両者を同格に見せない。

### P2-5. 権利確認未完了のまま素材を予定している（Codex）

- 表紙・デモ・キャプチャで使う全素材を先に固定し、生成元・入力素材・利用条件・加工者を確認。確認不能な素材は使用しない提出前ゲートにする。

### P2-6. 都議選対比61.53%は諸刃（Claude）

- 2025都議選は歴史的に特異に高い年（2021年は42.39%）。「身近なほど低い」の一般化に使うと突っ込める。削除がより安全。

### P2-7. ①フックと②課題の接続がジグザグ（Claude）

- 「自分ごとの問い」→「社会課題の数字」→「自分ごとのUX」と視点が往復する。②冒頭を「——と聞かれて、答えられる人はほとんどいません。実際…」と接続すると滑らか。

## 要件適合の判定（Codex）

必須4要素・16:9・顔出し・キャプチャ・動画埋込・データ10件の要件認識は概ね正しい。ただし、動画を確実に再生する収録マスターの確定と、未確認アセットの権利処理が完了するまでは「要件適合済み」とは判断できない。
